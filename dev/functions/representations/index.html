Text serialization

Paulimorphic.@pauli_str — Macro
pauli"..." -> PauliStr

@pauli_str expr -> PauliStr

A custom string literal (and its underlying macro) that builds a PauliStr. When @pauli_str is directly invoked, any expression expr that evaluates (at runtime in the invoking scope) to either one of the following two types of input is accepted:

  • input::AbstractString: an optional phase marker followed by one Pauli character ('I', 'X', 'Y', or 'Z') per site. The subsequent evaluation is equivalent to toPauliStr(input).
  • input::AbstractVector{<:Integer} (only supported by @pauli_str): an integer vector where the k-th element is effectively a two-bit code of PauliSym that specifies the Pauli operator acting on site k. The subsequent evaluation is equivalent to toPauliStr(input, PhaseFactor(0)).
Info

In both forms, the k-th Pauli character (or integer) of input specifies the single-site Pauli operator acting on site k, and the resulting PauliStr spans (verifiable via countSites) as many sites as the count of Pauli letters (or integers). A phase marker alone (e.g., pauli"-") therefore yields a zero-site string carrying that phase.

Examples

julia> pauli"IZXY" == (@pauli_str [0, 1, 2, 3]) == @pauli_str([0, 1, 2, 3])
true

julia> let str="IX", lst=[0, 2]; (@pauli_str str) == (@pauli_str lst) end
true

julia> pauli"-iXXIX" == PhaseFactor(3) * pauli"XXIX"
true

julia> (@pauli_str toString(pauli"-XXIX", denseString=true)) == pauli"-XXIX"
true

toPauliStr(str::AbstractString, fallbackStr::MissingOr{PauliStr}=missing) -> PauliStr

Parse str as a PauliStr. For str to be a valid string, it should be an optionally empty phase marker concatenated with a string of Pauli characters, each representing one of the four single-site Pauli operators ('I' $\mapsto \hat{I}$, 'Z' $\mapsto \hat{Z}$, 'X' $\mapsto \hat{X}$, 'Y' $\mapsto \hat{Y}$). The phase marker should be a prefix string equal to one of the valid markers: "+", "+i", "-", "-i", "", "i". When str is not a valid string to be fully parsed, an error identifying the violated condition is thrown if fallbackStr is missing (the default); otherwise fallbackStr is returned instead.

This method is effectively an inverse mapping to toString(::PauliStr, denseString=true):

julia> let str=pauli"-XIZX"; toPauliStr(toString(str, denseString=true)) == str end
true
Info

The parsing is case-sensitive: all Pauli characters must be uppercase, and the lowercase letter 'i' is always parsed as the imaginary unit of the phase marker.

source
toString(pStr::PauliStr; denseString::Bool=false, omitPlusSign::Bool=denseString) -> 
String

Return a String representation of pStr::PauliStr. The returned String is prefixed by the marker of pStr.phase, represented by "+", "+i", "-", or "-i". When omitPlusSign=true, the character '+' is omitted.

When denseString=false (the default sparse representation), identity sites are omitted and each non-identity Pauli character carries its (1-based) site index as a subscript (e.g., "+X₁X₂X₄"). The body (excluding the phase prefix) also collapses to "I" whenever every site carries the identity (including the zero-site case).

When denseString=true (the dense representation), every site in 1:pStr.n emits one character ('I', 'X', 'Y', or 'Z'). In this format, the returned value can be accepted by @pauli_str as a string literal.

Info

When pStr is a zero-site string, the body of the returned string (after the phase prefix) is "I", so parsing it back with @pauli_str yields a single-site identity rather than a zero-site string:

julia> countSites(@pauli_str toString(pauli"-", denseString=true)) == 1
true

Examples

julia> toString(pauli"XXIX")
"+X₁X₂X₄"

julia> toString(pauli"XXIX", denseString=true)
"XXIX"

julia> toString(pauli"-iXXIX", denseString=true)
"-iXXIX"

julia> let s = pauli"-XXIX"; (@pauli_str toString(s, denseString=true)) == s end
true

Paulimorphic.genJordanWignerEnc — Function
genJordanWignerEnc(nMode::Integer, nSite::Integer=nMode) -> 
Pair{Vector{PauliStr}, Vector{PauliStr}}

Generate the Jordan–Wigner encoding of nMode fermionic modes as a Majorana encoding (see checkMajoranaEnc): a collection of 2nMode Hermitian, mutually anticommuting Pauli strings, each explicitly acting on nSite sites. Mode p is associated with the Majorana-operator pair,

\[\hat{\gamma}_{2p-1} = \hat{Z}_1 \cdots \hat{Z}_{p-1} \hat{X}_p, \qquad \hat{\gamma}_{2p} = \hat{Z}_1 \cdots \hat{Z}_{p-1} \hat{Y}_p.\]

As a result, the expression of each occupation-number vector state remains unchanged in the Pauli-Z basis:

\[\lvert n_1, n_2, \ldots, n_p, \ldots \rangle \mapsto \lvert n_1, n_2, \ldots, n_p, \ldots \rangle.\]

The maximum Pauli weight (i.e., the number of non-identity single-qubit Pauli operators) of PauliStr generated by this encoding grows linearly with nMode. nMode must be positive and nSite must be no less than nMode. When nSite > nMode, every site above nMode carries the identity.

Returned format

The encoding is returned as a res::Pair such that the Majorana operators with odd indices ($\hat{\gamma}_{2p-1}$) are stored in res.first and Majorana operators with even indices ($\hat{\gamma}_{2p}$) are stored in res.second.

Paulimorphic.genParityEnc — Function
genParityEnc(nMode::Integer, nSite::Integer=nMode) -> 
Pair{Vector{PauliStr}, Vector{PauliStr}}

Generate the parity encoding of nMode fermionic modes as a Majorana encoding (see checkMajoranaEnc): a collection of 2nMode Hermitian, mutually anticommuting Pauli strings, each explicitly acting on nSite sites. Mode p is associated with the Majorana-operator pair,

\[\hat{\gamma}_{2p-1} = \hat{Z}_{p-1} \hat{X}_p \hat{X}_{p+1} \cdots \hat{X}_{\mathtt{nMode}}, \qquad \hat{\gamma}_{2p} = \hat{Y}_p \hat{X}_{p+1} \cdots \hat{X}_{\mathtt{nMode}},\]

where $\hat{Z}_{p-1}$ is absent for p == 1.

As a result, site j stores the parity of the first j mode occupancies, making the encoding the prefix-sum dual of the Jordan–Wigner encoding. Each occupation-number vector state is represented by its prefix-parity counterpart in the Pauli-Z basis:

\[\lvert n_1, n_2, \ldots, n_p, \ldots \rangle \mapsto \lvert n_1, n_1 \veebar n_2, \ldots, n_1 \veebar \cdots \veebar n_p, \ldots \rangle,\]

where $\veebar$ denotes the XOR (exclusive or) operation on the binary occupation numbers (i.e., addition modulo 2).

The maximum Pauli weight (i.e., the number of non-identity single-qubit Pauli operators) of PauliStr generated by this encoding grows linearly with nMode. nMode must be positive and nSite must be no less than nMode. When nSite > nMode, every site above nMode carries the identity.

Returned format

The encoding is returned as a res::Pair such that the Majorana operators with odd indices ($\hat{\gamma}_{2p-1}$) are stored in res.first and Majorana operators with even indices ($\hat{\gamma}_{2p}$) are stored in res.second.

Paulimorphic.genBravyiKitaevEnc — Function
genBravyiKitaevEnc(nMode::Integer, nSite::Integer=nMode) -> 
Pair{Vector{PauliStr}, Vector{PauliStr}}

Generate the Bravyi–Kitaev encoding of nMode fermionic modes as a Majorana encoding (see checkMajoranaEnc): a collection of 2nMode Hermitian, mutually anticommuting Pauli strings, each explicitly acting on nSite sites. Mode p is associated with the Majorana-operator pair,

\[\hat{\gamma}_{2p-1} = \hat{X}_{U(p)} \hat{X}_p \hat{Z}_{P(p)}, \qquad \hat{\gamma}_{2p} = \hat{X}_{U(p)} \hat{Y}_p \hat{Z}_{P(p) \setminus F(p)},\]

where the update set $U(p)$, parity set $P(p)$, and flip set $F(p)$ are the index sets (of mode p) determined by the Fenwick-tree (i.e., binary-indexed-tree) structure over an arbitrary (positive) number nMode of modes, following the formulation of the encoding for electronic-structure problems in this review. The maximum Pauli weight (i.e., the number of non-identity single-qubit Pauli operators) of PauliStr generated by this encoding grows as $\mathcal{O}(\log \mathtt{nMode})$. nMode must be positive and nSite must be no less than nMode. When nSite > nMode, every site above nMode carries the identity.

Returned format

The encoding is returned as a res::Pair such that the Majorana operators with odd indices ($\hat{\gamma}_{2p-1}$) are stored in res.first and Majorana operators with even indices ($\hat{\gamma}_{2p}$) are stored in res.second.

Paulimorphic.toMajoranaPair — Function
toMajoranaPair(opPair::Pair{<:PauliSum, <:PauliSum}, checkForDiracPair::Bool=true) -> 
Pair{<:PauliSum, <:PauliSum}

Convert a single-mode Dirac-operator pair opPair, in which opPair.first and opPair.second respectively represent the annihilation operator $\hat{a}$ and the creation operator $\hat{c}$ of the same fermionic mode, into the corresponding pair of Majorana operators returned as res, where res.first holds $\hat{a} + \hat{c}$ and res.second holds $\mathrm{i} \, (\hat{c} - \hat{a})$.

When checkForDiracPair=true, opPair is first verified to form a valid single-mode Dirac pair; any violation is reported by a thrown error, and both operators must explicitly act on the same number of sites for the verification to pass. When checkForDiracPair=false, the verification is skipped, in which case the output is physically meaningful only when the input is a valid Dirac-operator pair. The two operators held by res are in the canonical form and do not reference any data in opPair.

Examples

julia> dEnc = toDiracEnc(genJordanWignerEnc(1));

julia> mPair = toMajoranaPair(dEnc.first[1] => dEnc.second[1]);

julia> mPair == (PauliSum(Int, [pauli"X"]) => PauliSum(Int, [pauli"Y"]))
true

Paulimorphic.toDiracEnc — Function
toDiracEnc(::Type{T}, enc::Pair{<:AbstractVector{PauliStr}, <:AbstractVector{PauliStr}} 
           ) where {T<:Union{AbstractFloat, Signed, Rational{<:Signed}}} -> 
Pair{Vector{ PauliSum{T} }, Vector{ PauliSum{T} }}

toDiracEnc(enc::Pair{<:AbstractVector{PauliStr}, <:AbstractVector{PauliStr}}) -> 
Pair{Vector{ PauliSum{Rational{Int}} }, Vector{ PauliSum{Rational{Int}} }}

Convert a valid Majorana fermionic encoding enc (verified via checkMajoranaEnc with argument explicitError=true) of length(enc.first) fermionic modes to a Dirac fermionic encoding returned as res, whose stored annihilation operators $\hat{a}_p$ (at res.first[begin+p-1]) and creation operators $\hat{c}_p$ (at res.second[begin+p-1]) obey the following adjoint condition and anticommutation relations:

\[\hat{c}_p = \hat{a}_p^\dagger, \qquad \hat{a}_p \hat{c}_q + \hat{c}_q \hat{a}_p = \delta_{pq} \hat{I}, \qquad \hat{a}_p \hat{a}_q + \hat{a}_q \hat{a}_p = 0.\]

The relations between the Dirac (fermionic) operators and the Majorana operators are as follows:

\[\hat{a}_p = \frac{\hat{\gamma}_{2p-1} + \mathrm{i} \, \hat{\gamma}_{2p}}{2}, \qquad \hat{c}_p = \frac{\hat{\gamma}_{2p-1} - \mathrm{i} \, \hat{\gamma}_{2p}}{2},\]

where $\hat{\gamma}_{2p-1}$ and $\hat{\gamma}_{2p}$ denote enc.first[begin+p-1] and enc.second[begin+p-1], respectively. Each Dirac operator is a two-term canonical-form PauliSum. In the first method, T must be able to exactly represent 1//2 (e.g., a concrete AbstractFloat or Rational subtype); the second method falls back to the first method with T=Rational{Int}. The result in both methods does not reference any data in enc.

Paulimorphic.toMajoranaEnc — Function
toMajoranaEnc(::Type{PauliStr}, 
              enc::Pair{<:AbstractVector{<:PauliSum}, <:AbstractVector{<:PauliSum}}) -> 
Pair{Vector{PauliStr}, Vector{PauliStr}}

toMajoranaEnc(::Type{PauliSum}, 
              enc::Pair{<:AbstractVector{<:PauliSum}, <:AbstractVector{<:PauliSum}}) -> 
Pair{<:AbstractVector{<:PauliSum}, <:AbstractVector{<:PauliSum}}

toMajoranaEnc(enc::Pair{<:AbstractVector{<:PauliSum}, <:AbstractVector{<:PauliSum}}) -> 
Pair{Vector{PauliStr}, Vector{PauliStr}}

Convert a valid Dirac fermionic encoding enc (verified via checkDiracEnc) of length(enc.first) fermionic modes back to a Majorana encoding returned as res, acting as the inverse transformation of toDiracEnc. With $\hat{a}_p$ at enc.first[begin+p-1] and $\hat{c}_p = \hat{a}_p^\dagger$ at enc.second[begin+p-1], the recovered Majorana operators are constructed as

\[\hat{\gamma}_{2p-1} = \hat{c}_p + \hat{a}_p, \qquad \hat{\gamma}_{2p} = \mathrm{i} \, (\hat{c}_p - \hat{a}_p),\]

where $\hat{\gamma}_{2p-1}$ and $\hat{\gamma}_{2p}$ denote res.first[begin+p-1] and res.second[begin+p-1], respectively. In the first two method signatures, the first argument selects the output representation:

  • ::Type{PauliStr}: each recovered Majorana operator must be representable as a single PauliStr with a coefficient of exactly 1 or -1; equivalently, enc must satisfy checkDiracEnc(enc; strRestricted=true).
  • ::Type{PauliSum}: applicable to every valid Dirac encoding. Each recovered Majorana operator is stored as a (Hermitian) PauliSum, and the result satisfies the PauliSum-based method of checkMajoranaEnc.

The third method signature falls back to the first method signature.

In both representations, the result does not reference any data in enc. The PauliStr-based conversion and toDiracEnc are mutually inverse: 

julia> mEnc = genBravyiKitaevEnc(3);

julia> dEnc = toDiracEnc(mEnc);

julia> toMajoranaEnc(dEnc) == mEnc
true

julia> toDiracEnc(toMajoranaEnc(dEnc)) == dEnc
true

Paulimorphic.buildMajoranaFrame — Function
buildMajoranaFrame(enc::Pair{<:AbstractVector{<:PauliSum}, 
                             <:AbstractVector{<:PauliSum}}) -> 
Tuple{Pair{Matrix{T}, Matrix{T}}, Vector{PauliStr}} where {T<:Union{AbstractFloat, Signed, Rational{<:Signed}}}

Given a valid PauliSum-based Majorana encoding enc (verified via the matching method of checkMajoranaEnc) of nMode = length(enc.first) fermionic modes, attempt to rebuild its underlying PauliStr-based Majorana frame: 2nMode single Pauli strings frame (returned in ascending order, all carrying the positive-real phase) together with a pair of (real) transformation matrices matAnn => matCre, each of size 2nMode by nMode with element type T (the promoted real core type of the coefficients in enc), such that 

PauliSum(enc.first[ begin+i-1]) == PauliSum(frame, matAnn[:, i])
PauliSum(enc.second[begin+i-1]) == PauliSum(frame, matCre[:, i])

In other words, the return value is (matAnn=>matCre, frame). Furthermore, frame exists if and only if the number of distinct Pauli strings appearing across all operators in enc equals 2nMode, in which case hcat(matAnn, matCre) is exactly orthogonal and its columns list the odd-indexed Majorana operators followed by the even-indexed ones (a sorted-block ordering rather than the interleaved index ordering). When no such frame exists, the returned matrices are 0-by-0 and frame is empty. The returned frame carries no mode pairing or role assignment beyond its ascending string order. The result does not reference any data in enc.

                        inteData::Tuple{AbstractMatrix{C}, AbstractArray{C, 4}},

Validate the format of molecular integrals (first(inteData) as the one-body matrix and last(inteData) as the two-body tensor) of a single spin sector and return integral data (newInte1B, last(inteData)) that comply with the coefficient requirement for a second-quantized molecular electronic Hamiltonian under the PairedOrder format.

nOrbital sets the number of (spatial) orbitals in the sector to constrain the sizes of tensors in inteData via checkNBodyInteTensor, which also takes in hermiticity and idxPairSymm as the values for the symmetry-assertion arguments with the same names, respectively. Since one spin sector draws on a single spatial-orbital set, idxPairSymm applies to the index pairs of both tensors; its default value asserts the index-pair transposition symmetry exactly when the tensors are real and pairwise Hermitian, matching the symmetry of real spatial orbitals under the Coulomb interaction.

Reformatted one-body integrals

The first element of the returned integral data, newInte1B, is the result of subtracting the coefficient matrix of a specific two-index two-body term in the Hamiltonian under the PairedOrder format from first(inteData):

newInte1B[i, j] == 
first(inteData)[i, j] - (1/2) * sum(last(inteData)[i, k, k, j] for k in 1:nOrbital)

This correction on the one-body matrix derives from the two-body operator monomial identity

\[\hat{c}_i \hat{a}_j \hat{c}_k \hat{a}_l = \hat{c}_i \hat{c}_k \hat{a}_l \hat{a}_j + \delta_{jk} \, \hat{c}_i \hat{a}_l\]

so that assembling the PairedOrder two-body sum with the corrected one-body matrix produces a PairedOrder encoding equivalent to the NormalOrder encoding of the same molecular electronic Hamiltonian.

Info

The returned one-body matrix is freshly allocated with a potentially promoted element type (e.g., Int inputs promote to Float64, while float, rational, and complex element types are preserved), whereas the returned two-body tensor is exactly last(inteData), not a copy.

Paulimorphic.genNBodyOperatorSum — Function
genNBodyOperatorSum(format::NBodyOrdering, 
                    enc::NTuple{2, Pair{<:AbstractVector{<:PauliSum}, 
                                        <:AbstractVector{<:PauliSum}}}, 
                    orbInte::AbstractArray{C, D}, spinSecConfig::NTuple{N, Bool}, 
                    iModeStart::NTuple{N, Integer}=ntuple(_->1, Val(N)); 
                    particleExch::Bool=true, 
                    hermiticity::Bool=true, 
                    idxPairSymm::NTuple{N, Bool}=ntuple(_->false, Val(N)), 
                    checkInput::Bool=true) where 
                   {T<:Union{AbstractFloat, Signed, Rational{<:Signed}}, C<:Union{Complex{T}, T}, D, N} -> 
PauliSum

Return a spin-1/2 N-particle operator summation as the linear combination of products of PauliSum provided by the input encoding enc. The linear coefficients of the PauliSum products are specified by the N-particle integral tensor orbInte (D == 2N), whose axes follow the index-pair layout: axes (2k-1, 2k) host the index pair $(c_k, a_k)$ of the k-th particle (1 <= k <= N), where $c_k$ and $a_k$ respectively label the modes of its creation and annihilation operators. Specifically, the index $c_k$ (or $a_k$) is incremented by iModeStart[begin+k-1] - 1 to give the mode (index) of the corresponding operator in the spin sector specified by spinSecConfig[begin+k-1]. Subsequently, the returned summation is evaluated as 

prefactor * sum(orbInte[idx] * monomial(idx) for idx in CartesianIndices(orbInte))

where each monomial(idx) is generated by genNBodyOperator in the operator ordering determined by format; the value of prefactor is set based on particleExch following two validation protocols:

  • particleExch=true: the core operator underlying the integration expression for orbInte is asserted to be invariant under exchanging the particle coordinates of the many-particle wavefunctions it acts on. Consequently, particles sharing both the same spin sector and the same mode window (range of modes indexing a subset of mode operators in enc) form interchangeable classes. Accordingly, prefactor is set to the inverse of the product of the class-size factorials, compensating the over-counting of unordered particle selections by ordered indices in the summation. Simultaneously, the axes of orbInte that are associated with the same spin sectors but different mode windows must occupy disjoint windows (i.e., no partially shared mode indices are allowed). When checkInput=true, the consistency between the index-pair exchange symmetry of orbInte and the (index pairs for the) interchangeable classes determined by spinSecConfig and iModeStart, is checked.

  • particleExch=false: every entry of orbInte is the literal coefficient of its monomial, meaning prefactor is fixed at 1, and no exchange symmetry is validated for orbInte or assumed for its underlying operator. As a result, tensor elements with distinct indices may be added together to be associated with the same operator monomial (after reforming them in canonical form), e.g., for any two distinct modes $i$ and $j$:

    \[ \hat{c}_i \hat{c}_j \hat{a}_j \hat{a}_i = \hat{c}_j \hat{c}_i \hat{a}_i \hat{a}_j.\]

Aside from particleExch, there are two more optional keyword arguments that are used to validate the structure of orbInte when checkInput=true:

  • hermiticity=true: orbInte must have pairwise Hermiticity (checked via checkInteHermiticity). Under particleExch=true, this Hermiticity guarantees the Hermiticity of the returned operator summation; under particleExch=false, it only guarantees the same operator-summation Hermiticity when format = NormalOrder().

  • idxPairSymm[begin+k-1]=true: orbInte must have index-pair transposition symmetry for the k-th particle (checked via checkIntePairTransposition).

Info

When checkInput is set to true, enc is also checked via checkSpinSectoredEnc, and each mode window is checked against the capacity of its sector in enc.

encodeElecHam(format::NBodyOrdering, 
              enc::Union{NTuple{2, Pair{<:AbstractVector{<:PauliSum}, 
                                        <:AbstractVector{<:PauliSum}}}, 
                         Pair{<:AbstractVector{<:PauliSum}, 
                              <:AbstractVector{<:PauliSum}}}, 
              inte1B2BSpin1::Tuple{AbstractMatrix{C}, AbstractArray{C, 4}}, 
              inte1B2BSpin2::Tuple{AbstractMatrix{C}, AbstractArray{C, 4}}, 
              inte2BCross::AbstractArray{C, 4}, checkEncoding::Bool=true; 
              hermiticity::Bool=true, 
              idxPairSymm::NTuple{2, Bool}=ntuple(_->(hermiticity && C<:Real), 2)
              ) where {T<:Union{AbstractFloat, Signed, Rational{<:Signed}}, C<:Union{Complex{T}, T}} -> 
PauliSum

Return a PauliSum-based encoding (representation) of the molecular electronic Hamiltonian

\[\hat{H}_{\mathrm{elec}} = \sum_s \hat{H}_s + \sum_{i,j,k,l} \mathtt{inte2BCross}[i,j,k,l] \, \hat{c}_{i,1} \hat{c}_{k,2} \hat{a}_{l,2} \hat{a}_{j,1},\]

where $\hat{c}_{i,s} = \hat{a}_{i,s}^\dagger$ is the Dirac creation operator for mode i in spin sector s, represented by products of single-mode fermionic operators from the input encoding enc reordered by formatSpinSectoredEnc(enc) whose validity checking is controlled by the same-named argument checkEncoding; inte2BCross is the cross-spin-sector two-body spatial molecular integral tensor and $\hat{H}_s$ is a per-spin-sector Hamiltonian fragment

\[\hat{H}_s = \sum_{i,j} h^{(1)}_s[i,j] \, \hat{c}_{i,s} \hat{a}_{j,s} + \frac{1}{2} \sum_{i,j,k,l} h^{(2)}_s[i,j,k,l] \, \hat{c}_{i,s} \hat{c}_{k,s} \hat{a}_{l,s} \hat{a}_{j,s},\]

with $h^{(1)}_s$ and $h^{(2)}_s$ respectively denoting the one-body and two-body tensors of per-spin-sector molecular integrals at different values of $s$:

  • $s = 1$: first(inte1B2BSpin1), last(inte1B2BSpin1)

  • $s = 2$: first(inte1B2BSpin2), last(inte1B2BSpin2)

Both per-spin-sector two-body tensors, as well as inte2BCross, follow the index-pair layout (i.e., the Chemist notation for two-body molecular integrals); the numbers of spatial-orbital modes per spin sector, nMode1 and nMode2, are inferred from size(inte2BCross) == (nMode1, nMode1, nMode2, nMode2). Hence, the per-spin-sector tensors must match these counts, whereas the total number of spin-orbital modes covered by enc can exceed nMode1 + nMode2.

Deciding the ordering of two-body terms

The form of the two-body terms in $\hat{H}_{\mathrm{elec}}$ (as well as in $\hat{H}_s$) described above,

\[\hat{c}_{i,s_1} \hat{c}_{k,s_2} \hat{a}_{l,s_2} \hat{a}_{j,s_1},\]

follows the normal ordering convention, which can be enforced upon the returned encoding by setting format = NormalOrder(). Alternatively, format = PairedOrder() encodes the two-body term in the form (associated with the same two-body tensor)

\[\hat{c}_{i,s_1} \hat{a}_{j,s_1} \hat{c}_{k,s_2} \hat{a}_{l,s_2}.\]

Consequently, for the resulting encoding to represent the same electronic Hamiltonian, the coefficient matrix for the one-body terms ($\hat{c}_{i,s} \hat{a}_{j,s}$) can no longer directly be the one-body tensor (e.g., first(inte1B2BSpin1)), but is obtained by subtracting a correction matrix, whose $(i, j)$ element is

\[\frac{1}{2} \sum_k h^{(2)}_s[i, k, k, j],\]

from the one-body tensor. This correction is carried out automatically (via formatMolecularInteData) when format = PairedOrder(), hence encodeElecHam always returns an equivalent encoding for the same input molecular integral tensors (i.e., preserving the eigenspectrum of the underlying electronic Hamiltonian) regardless of the value of format.

Symmetry assertion

In both method signatures of encodeElecHam, keyword argument hermiticity (true by default) asserts the pairwise Hermiticity of all the input integral tensors (from inte1B2BSpin1, from inte1B2BSpin2, and inte2BCross), and each element of idxPairSymm asserts the index-pair transposition symmetry in each spin sector for these tensors, which is imposed by the default value of idxPairSymm exactly when the tensors are real and pairwise Hermitian, matching the symmetry of real spatial orbitals under the Coulomb interaction. As a result, encodeElecHam (with default argument values) assumes that the input per-spin-sector two-body tensors hold an eight-fold symmetry (two-fold particle-exchange times four-fold index-pair transposition) as long as their elements are all real.
