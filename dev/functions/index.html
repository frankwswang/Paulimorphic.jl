Paulimorphic.@pauli_str — Macro
pauli"..." -> PauliStr

@pauli_str expr -> PauliStr

A custom string literal (and its underlying macro) that builds a PauliStr. When @pauli_str is directly invoked, any expression expr that evaluates (at runtime in the invoking scope) to either one of the following two types of input is accepted:

  • input::AbstractString: an optional phase marker followed by one Pauli character ('I', 'X', 'Y', or 'Z') per site. The subsequent evaluation is equivalent to toPauliStr(input).
  • input::AbstractVector{<:Integer} (only supported by @pauli_str): an integer vector where the k-th element is effectively a two-bit code of PauliSym that specifies the Pauli operator acting on site k. The subsequent evaluation is equivalent to toPauliStr(input, PhaseFactor(0)).
Info

In both forms, the k-th Pauli character (or integer) of input specifies the single-site Pauli operator acting on site k, and the resulting PauliStr spans (verifiable via countSites) as many sites as the count of Pauli letters (or integers). A phase marker alone (e.g., pauli"-") therefore yields a zero-site string carrying that phase.

Examples

julia> pauli"IZXY" == (@pauli_str [0, 1, 2, 3]) == @pauli_str([0, 1, 2, 3])
true

julia> let str="IX", lst=[0, 2]; (@pauli_str str) == (@pauli_str lst) end
true

julia> pauli"-iXXIX" == PhaseFactor(3) * pauli"XXIX"
true

julia> (@pauli_str toString(pauli"-XXIX", denseString=true)) == pauli"-XXIX"
true

Paulimorphic.breadthFirstSearch — Method
breadthFirstSearch(f, graph::StrictGraph{T}, startingPoint::Union{Missing, T}, 
                   cache!Self::AbstractVector{T}=zeros(T, graph.order)
                   ) where {T<:Integer} -> 
Tuple{T, Int}

Perform a breadth-first search (BFS) on graph, starting from startingPoint.

If startingPoint === missing, the search visits all connected components, iterating through vertices in 1:graph.order as deterministic component roots. If startingPoint is a vertex label, only the connected component reachable from startingPoint is searched.

The predicate f is called once for each dequeued vertex as f(v)::Bool. If f(v) returns true, the search terminates immediately and returns (v, nVisited), where v::T is the first vertex satisfying f, and nVisited is the number of vertices dequeued, equivalently the number of calls to f. If no vertex satisfies f, the function returns (zero(T), nVisited), the sentinel value for "not found".

The optional cache!Self is used as a buffer to store the deterministic BFS queue. It must have length at least graph.order. The elements of cache!Self up to the returned nVisited position contain the BFS discovery order.

Paulimorphic.buildMajoranaFrame — Method
buildMajoranaFrame(enc::Pair{<:AbstractVector{<:PauliSum}, 
                             <:AbstractVector{<:PauliSum}}) -> 
Tuple{Pair{Matrix{T}, Matrix{T}}, Vector{PauliStr}} where {T<:Union{AbstractFloat, Signed, Rational{<:Signed}}}

Given a valid PauliSum-based Majorana encoding enc (verified via the matching method of checkMajoranaEnc) of nMode = length(enc.first) fermionic modes, attempt to rebuild its underlying PauliStr-based Majorana frame: 2nMode single Pauli strings frame (returned in ascending order, all carrying the positive-real phase) together with a pair of (real) transformation matrices matAnn => matCre, each of size 2nMode by nMode with element type T (the promoted real core type of the coefficients in enc), such that 

PauliSum(enc.first[ begin+i-1]) == PauliSum(frame, matAnn[:, i])
PauliSum(enc.second[begin+i-1]) == PauliSum(frame, matCre[:, i])

In other words, the return value is (matAnn=>matCre, frame). Furthermore, frame exists if and only if the number of distinct Pauli strings appearing across all operators in enc equals 2nMode, in which case hcat(matAnn, matCre) is exactly orthogonal and its columns list the odd-indexed Majorana operators followed by the even-indexed ones (a sorted-block ordering rather than the interleaved index ordering). When no such frame exists, the returned matrices are 0-by-0 and frame is empty. The returned frame carries no mode pairing or role assignment beyond its ascending string order. The result does not reference any data in enc.

Paulimorphic.canonicalize! — Method
canonicalize!(ham::PauliSum) -> PauliSum

Rewrite ham into a canonical form in place and return it: absorb every string's phase into its coefficient (stored in ham.coeff), then sort the Pauli terms into a deterministic total order based on Paulimorphic.sortStrings!.

This function preserves the term count. In other words, it does not merge duplicate strings or drop zero coefficients. To obtain a (unlinked) merged form, rebuild the sum via PauliSum(ham, true).

Paulimorphic.checkDiracEnc — Function
checkDiracEnc(enc::Pair{<:AbstractVector{<:PauliSum}, <:AbstractVector{<:PauliSum}}, 
              explicitError::Bool=false; strRestricted::Bool=false) -> 
Bool

Return true if enc forms a valid Dirac fermionic encoding. It must contain a Pair of AbstractVector, each holding nMode = length(enc.first) operators (nMode > 0) represented by PauliSum. Specifically, enc.first and enc.second must respectively store the annihilation operators $\hat{a}_p$ (at enc.first[begin+p-1]) and the creation operators $\hat{c}_p$ (at enc.second[begin+p-1]), which obey the following adjoint condition and anticommutation relations:

\[\hat{c}_p = \hat{a}_p^\dagger, \qquad \hat{a}_p \hat{c}_q + \hat{c}_q \hat{a}_p = \delta_{pq} \hat{I}, \qquad \hat{a}_p \hat{a}_q + \hat{a}_q \hat{a}_p = 0\]

for every mode pair (p, q). The adjoint condition is checked structurally (via Paulimorphic.toAdjoint). The verified anticommutation relations are invariant under swapping enc.first and enc.second, so the annihilation-versus-creation role assignment is a positional convention carried by the Pair structure rather than a checkable property.

Additionally, enc must be formatted such that

  • All contained PauliSum are in the canonical form (see PauliSum and canonicalize! for more details)
  • All contained PauliSum explicitly act on the same number of sites (i.e., countSites returns the same value)

When strRestricted=true, enc must additionally be convertible to a Pauli-string-based Majorana encoding: for each mode p, $\hat{a}_p + \hat{c}_p$ and $\mathrm{i} \, (\hat{c}_p - \hat{a}_p)$ must each be representable as a PauliStr with a phase of exactly 1 or -1. Under the default strRestricted=false, encodings whose modes are represented as PauliSum beyond containing a single PauliStr are accepted as long as they satisfy the Hermitian adjoint condition and the anticommutation relations.

All operator comparisons are exact, so an encoding whose coefficients are subject to floating-point errors (e.g., mode-mixing amplitudes that are not exactly representable) can fail the verification despite being valid in exact arithmetic; exact coefficient types (e.g., Rational subtypes) do not have this limitation.

When enc fails to meet any necessary condition to form such an encoding, the failure is reported by returning false unless explicitError=true, in which case an ArgumentError identifying the violated condition (and the immediate offending operators) is thrown instead.

Paulimorphic.checkInteHermiticity — Method
checkInteHermiticity(inte::AbstractArray{C, D}, explicitError::Bool=false) where 
                    {T<:Real, C<:Union{Complex{T}, T}, D} -> 
Bool

Return true if inte, an N-particle integral tensor (N=D÷2), whose axes follow the index-pair layout, is Hermitian under simultaneously transposing every index pair $(c_k, a_k)$. Specifically, axes (2k-1, 2k) of inte must host $(c_k, a_k)$ for the k-th particle, with the value of $c_k$ labeling a creation operator and the value of $a_k$ labeling an annihilation operator. In other words, inte must satisfy

\[\mathtt{inte}[c_1, a_1, \ldots, c_N, a_N] = \mathtt{inte}[a_1, c_1, \ldots, a_N, c_N]^{*},\]

where ${}^{*}$ denotes the complex conjugate and $[\ldots,\ldots]$ represents the multi-dimensional index for inte.

If inte does not hold this symmetry, checkInteHermiticity returns false, or throws an error when explicitError is set to true. The tensor rank of inte, D, must be even; for every index pair, their corresponding axes must have equal extents.

Paulimorphic.checkIntePairTransposition — Method
checkIntePairTransposition(inte::AbstractArray{C, D}, pos::Integer, 
                           explicitError::Bool=false) where 
                          {T<:Real, C<:Union{Complex{T}, T}, D} -> 
Bool

Return true if inte, an N-particle integral tensor (N=D÷2) whose axes follow the index-pair layout (axes (2k-1, 2k) host the index pair $(c_k, a_k)$ of the k-th particle), is invariant under transposing the index pair of particle k = pos (1 <= k <= N):

\[\mathtt{inte}[\ldots, c_k, a_k, \ldots] = \mathtt{inte}[\ldots, a_k, c_k, \ldots]\]

An integral tensor

\[\mathtt{inte}[c_1, a_1, \ldots, c_N, a_N] = \int \mathrm{d}x_1 \cdots \mathrm{d}x_N \, \hat{O}\llbracket f_{c_1}^{*}, f_{a_1}, \ldots, f_{c_N}^{*}, f_{a_N} \rrbracket (x_1, \ldots, x_N)\]

may hold such a symmetry when the action of the underlying core operator $\hat{O}$ onto all the basis wavefunctions $f$ indexed by $(c_1, a_1, \ldots, c_N, a_N)$ is invariant under the transposition of $(c_k, a_k)$ inside the integration expression. For example, when $\hat{O}$ is the Coulomb operator ($1/r_{12}$), its corresponding two-particle integral tensor holds a four-fold symmetry of this type as long as all the basis wavefunctions used for the integration are real.

If inte does not hold this symmetry, checkIntePairTransposition returns false, or throws an error when explicitError is set to true. The tensor rank of inte, D, must be even; the axes hosting $(c_k, a_k)$ must have equal extents.

Paulimorphic.checkInteParticleExchange — Method
checkInteParticleExchange(inte::AbstractArray{C, D}, posPair::NTuple{2, Integer}, 
                          explicitError::Bool=false) where 
                         {T<:Real, C<:Union{Complex{T}, T}, D} -> 
Bool

Return true if inte, an N-particle integral tensor (N=D÷2) whose axes follow the index-pair layout (axes (2k-1, 2k) host the index pair $(c_k, a_k)$ of the k-th particle), is invariant under exchanging the index pairs of the two particles k and l with (k, l) = posPair:

\[\mathtt{inte}[\ldots, c_k, a_k, \ldots, c_l, a_l, \ldots] = \mathtt{inte}[\ldots, c_l, a_l, \ldots, c_k, a_k, \ldots]\]

An integral tensor may hold this symmetry when the underlying core operator $\hat{O}(x_1, \ldots, x_N)$ is invariant under exchanging the respective coordinates of particles k and l, $x_k$ and $x_l$. In other words, these N particles are considered identical with respect to operations (e.g., interactions) characterized by $\hat{O}$.

If inte does not hold this symmetry, checkInteParticleExchange returns false, or throws an error when explicitError is set to true. The tensor rank of inte, D, must be even; the axes hosting the index pairs of particles k and l must have equal extents. In the case of k == l, i.e., no distinct particles are exchanged, checkInteParticleExchange always returns true.

Paulimorphic.checkMajoranaEnc — Function
checkMajoranaEnc(enc::Pair{<:AbstractVector{PauliStr}, <:AbstractVector{PauliStr}},

checkMajoranaEnc(enc::Pair{<:AbstractVector{<:PauliSum}, <:AbstractVector{<:PauliSum}},

Return true if enc forms a valid PauliStr-based or PauliSum-based Majorana encoding of length(enc.first) fermionic modes, where enc.first and enc.second respectively store the odd-indexed ($\hat{\gamma}_{2p-1}$) and even-indexed ($\hat{\gamma}_{2p}$) Majorana operators. Every stored operator $\hat{\gamma}_i$ must be Hermitian and the operators must also satisfy the following anticommutation relation:

\[\hat{\gamma}_i \hat{\gamma}_j + \hat{\gamma}_j \hat{\gamma}_i = 2 \delta_{ij} \hat{I}.\]

Note that this validity class is disjoint from the one verified by checkDiracEnc.

When enc fails to meet any necessary condition to form such an encoding, the failure is reported by returning false unless explicitError=true, in which case an error identifying the violated condition (and the immediate offending operators) is thrown instead.

Paulimorphic.checkNBodyInteTensor — Method
checkNBodyInteTensor(inte::AbstractArray{C, D}, nOrb::NTuple{N, Integer}, 
                     orbSecLabel::NTuple{N, Integer}, 
                     idxPairSymm::NTuple{N, Bool}, 
                     explicitError::Bool=false; 
                     particleExch::Bool=true, 
                     hermiticity::Bool=true) where 
                    {T<:Real, C<:Union{Complex{T}, T}, D, N} -> 
Bool

Return true if inte is an N-particle integral tensor (N == D÷2 >= 1), given a tuple of orbital-sector extents nOrb (i.e., nOrb[begin+k-1] specifies the mode count for the k-th particle), the orbital-sector labels orbSecLabel (particles sharing a label draw from the same orbital set), and the index-pair transposition symmetry flags. More specifically, idxPairSymm[begin+k-1] indicates whether $\mathtt{inte}[\ldots, c_k, a_k, \ldots]$ is invariant under the transposition of the index pair $(c_k, a_k)$. For inte to be a valid integral tensor, its axes must follow the index-pair layout: axes (2k-1, 2k) host the index pair $(c_k, a_k)$ of the k-th particle (1 <= k <= N). Therefore, the size of inte must satisfy 

size(inte) == Tuple(repeat(collect(nOrb), inner=2))

(i.e., every extent of nOrb repeated twice, in order), and the axes sharing the same orbital-sector label must also have the same extents.

In addition to the shape of inte, the following symmetries are (at least partially) checked based on the values of the configurational arguments:

  • Hermiticity (when hermiticity=true): inte must be Hermitian under simultaneously transposing every index pair (via checkInteHermiticity).
  • Particle-exchange invariance (when particleExch=true): inte must be invariant under exchanging the index pairs of every two particles within the same orbital sector specified by orbSecLabel (via checkInteParticleExchange). This invariance holds under the assumption that the underlying operator for the integration expression of inte has particle (coordinate) exchange symmetry.
  • Index-pair transposition invariance: inte must be invariant under transposing the index pair of every particle whose orbital sector is flagged as true by idxPairSymm (via checkIntePairTransposition).

If any above symmetry check fails, or the size of inte does not match nOrb, checkNBodyInteTensor returns false, or throws an error when explicitError is set to true. Furthermore, the function throws an error regardless of the value of explicitError if any configurational arguments (including nOrb) are not in valid forms (e.g., nOrb containing any negative elements).

Info

When particleExch=true, for idxPairSymm to be in a valid form (aside from being of the allowed type), idxPairSymm must have the same equality pattern as orbSecLabel. In other words, for any two particles i and j (1<=i<=j<=N), orbSecLabel[begin+i-1] == orbSecLabel[begin+j-1] must imply idxPairSymm[begin+i-1] == idxPairSymm[begin+j-1].

Paulimorphic.curtail — Method
curtail(ham::PauliSum{T}, tolerance::Real=(T<:AbstractFloat ? 8eps(T) : zero(T)); 
        relative::Bool=false, inclusive::Bool=false) where {T<:Union{AbstractFloat, Signed, Rational{<:Signed}}} -> 
PauliSum{T}

Return a filtered shallow copy of ham with negligible terms removed, retaining only the terms whose coefficient exceeds a threshold. A term with coefficient c is kept when

abs(c) >  tolerance * scale    # `inclusive == false`
abs(c) >= tolerance * scale    # `inclusive == true`

where scale is one(T) when relative=false (default) and maximum(abs, ham.coeff) when relative=true. Thus, tolerance acts as an absolute magnitude floor by default, or as a fraction of the largest coefficient when relative is set. The inclusive keyword chooses whether coefficients landing exactly on the threshold are kept (>=) or dropped (>). For floating-point T, the default value of tolerance is 8eps(T): a small multiple of the machine epsilon, enough to discard the round-off residuals left by operator assembly when the coefficients are well conditioned; for integer T, the default value of tolerance is zero(T).

String ownership

The retained terms remain in ham's order, and the returned sum's coefficients are held in an independent buffer. Its PauliStrs, however, are NOT reconstructed (deep-copied). In other words, the returned sum's .str entries are the same (subsets of) PauliStr held by ham.str.

\[\hat{H}_{\mathrm{elec}} = \sum_s \hat{H}_s + \sum_{i,j,k,l} \mathtt{inte2BCross}[i,j,k,l] \, \hat{c}_{i,1} \hat{c}_{k,2} \hat{a}_{l,2} \hat{a}_{j,1},\]

where $\hat{c}_{i,s} = \hat{a}_{i,s}^\dagger$ is the Dirac creation operator for mode i in spin sector s, represented by products of single-mode fermionic operators from the input encoding enc reordered by formatSpinSectoredEnc(enc) whose validity checking is controlled by the same-named argument checkEncoding; inte2BCross is the cross-spin-sector two-body spatial molecular integral tensor and $\hat{H}_s$ is a per-spin-sector Hamiltonian fragment

\[\hat{H}_s = \sum_{i,j} h^{(1)}_s[i,j] \, \hat{c}_{i,s} \hat{a}_{j,s} + \frac{1}{2} \sum_{i,j,k,l} h^{(2)}_s[i,j,k,l] \, \hat{c}_{i,s} \hat{c}_{k,s} \hat{a}_{l,s} \hat{a}_{j,s},\]

with $h^{(1)}_s$ and $h^{(2)}_s$ respectively denoting the one-body and two-body tensors of per-spin-sector molecular integrals at different values of $s$:

  • $s = 1$: first(inte1B2BSpin1), last(inte1B2BSpin1)

  • $s = 2$: first(inte1B2BSpin2), last(inte1B2BSpin2)

Both per-spin-sector two-body tensors, as well as inte2BCross, follow the index-pair layout (i.e., the Chemist notation for two-body molecular integrals); the numbers of spatial-orbital modes per spin sector, nMode1 and nMode2, are inferred from size(inte2BCross) == (nMode1, nMode1, nMode2, nMode2). Hence, the per-spin-sector tensors must match these counts, whereas the total number of spin-orbital modes covered by enc can exceed nMode1 + nMode2.

Deciding the ordering of two-body terms

The form of the two-body terms in $\hat{H}_{\mathrm{elec}}$ (as well as in $\hat{H}_s$) described above,

\[\hat{c}_{i,s_1} \hat{c}_{k,s_2} \hat{a}_{l,s_2} \hat{a}_{j,s_1},\]

follows the normal ordering convention, which can be enforced upon the returned encoding by setting format = NormalOrder(). Alternatively, format = PairedOrder() encodes the two-body term in the form (associated with the same two-body tensor)

\[\hat{c}_{i,s_1} \hat{a}_{j,s_1} \hat{c}_{k,s_2} \hat{a}_{l,s_2}.\]

Consequently, for the resulting encoding to represent the same electronic Hamiltonian, the coefficient matrix for the one-body terms ($\hat{c}_{i,s} \hat{a}_{j,s}$) can no longer directly be the one-body tensor (e.g., first(inte1B2BSpin1)), but is obtained by subtracting a correction matrix, whose $(i, j)$ element is

\[\frac{1}{2} \sum_k h^{(2)}_s[i, k, k, j],\]

from the one-body tensor. This correction is carried out automatically (via formatMolecularInteData) when format = PairedOrder(), hence encodeElecHam always returns an equivalent encoding for the same input molecular integral tensors (i.e., preserving the eigenspectrum of the underlying electronic Hamiltonian) regardless of the value of format.

Paulimorphic.genNBodyOperatorSum — Method
genNBodyOperatorSum(format::Paulimorphic.NBodyOrdering, 
                    enc::NTuple{2, Pair{<:AbstractVector{<:PauliSum}, 
                                        <:AbstractVector{<:PauliSum}}}, 
                    orbInte::AbstractArray{C, D}, spinSecConfig::NTuple{N, Bool}, 
                    iModeStart::NTuple{N, Integer}=ntuple(_->1, Val(N)); 
                    particleExch::Bool=true, 
                    hermiticity::Bool=true, 
                    idxPairSymm::NTuple{N, Bool}=ntuple(_->false, Val(N)), 
                    checkInput::Bool=true) where 
                   {T<:Real, C<:Union{Complex{T}, T}, D, N} -> 
PauliSum

Return a spin-1/2 N-particle operator summation as the linear combination of products of PauliSum provided by the input encoding enc. The linear coefficients of the PauliSum products are specified by the N-particle integral tensor orbInte (D == 2N), whose axes follow the index-pair layout: axes (2k-1, 2k) host the index pair $(c_k, a_k)$ of the k-th particle (1 <= k <= N), where $c_k$ and $a_k$ respectively label the modes of its creation and annihilation operators. Specifically, the index $c_k$ (or $a_k$) is incremented by iModeStart[begin+k-1] - 1 to give the mode (index) of the corresponding operator in the spin sector specified by spinSecConfig[begin+k-1]. Subsequently, the returned summation is evaluated as 

prefactor * sum(orbInte[idx] * monomial(idx) for idx in CartesianIndices(orbInte))

where each monomial(idx) is generated by genNBodyOperator in the operator ordering determined by format; the value of prefactor is set based on particleExch following two validation protocols:

  • particleExch=true: the core operator underlying the integration expression for orbInte is asserted to be invariant under exchanging the particle coordinates of the many-particle wavefunctions it acts on. Consequently, particles sharing both the same spin sector and the same mode window (range of modes indexing a subset of mode operators in enc) form interchangeable classes. Accordingly, prefactor is set to the inverse of the product of the class-size factorials, compensating the over-counting of unordered particle selections by ordered indices in the summation. Simultaneously, the axes of orbInte that are associated with the same spin sectors but different mode windows must occupy disjoint windows (i.e., no partially shared mode indices are allowed). When checkInput=true, the consistency between the index-pair exchange symmetry of orbInte and the (index pairs for the) interchangeable classes determined by spinSecConfig and iModeStart, is checked.

  • particleExch=false: every entry of orbInte is the literal coefficient of its monomial, meaning prefactor is fixed at 1, and no exchange symmetry is validated for orbInte or assumed for its underlying operator. As a result, tensor elements with distinct indices may be added together to be associated with the same operator monomial (after reforming them in canonical form), e.g., for any two distinct modes $i$ and $j$:

    \[ \hat{c}_i \hat{c}_j \hat{a}_j \hat{a}_i = \hat{c}_j \hat{c}_i \hat{a}_i \hat{a}_j.\]

Aside from particleExch, there are two more optional keyword arguments that are used to validate the structure of orbInte when checkInput=true:

  • hermiticity=true: orbInte must have pairwise Hermiticity (checked via checkInteHermiticity). Under particleExch=true, this Hermiticity guarantees the Hermiticity of the returned operator summation; under particleExch=false, it only guarantees the same operator-summation Hermiticity when format = NormalOrder().

  • idxPairSymm[begin+k-1]=true: orbInte must have index-pair transposition symmetry for the k-th particle (checked via checkIntePairTransposition).

Info

When checkInput is set to true, enc is also checked via checkSpinSectoredEnc, and each mode window is checked against the capacity of its sector in enc.

        filler::PauliSym=symI, simplification::Bool=true) where {T<:Union{AbstractFloat, Signed, Rational{<:Signed}}} -> 
PauliSum{T}

Convert a single-mode Dirac-operator pair opPair, in which opPair.first and opPair.second respectively represent the annihilation operator $\hat{a}$ and the creation operator $\hat{c}$ of the same fermionic mode, into the corresponding pair of Majorana operators returned as res, where res.first holds $\hat{a} + \hat{c}$ and res.second holds $\mathrm{i} \, (\hat{c} - \hat{a})$.

When checkForDiracPair=true, opPair is first verified to form a valid single-mode Dirac pair; any violation is reported by a thrown error, and both operators must explicitly act on the same number of sites for the verification to pass. When checkForDiracPair=false, the verification is skipped, in which case the output is physically meaningful only when the input is a valid Dirac-operator pair. The two operators held by res are in the canonical form and do not reference any data in opPair.

Examples

julia> dEnc = toDiracEnc(genJordanWignerEnc(1));

julia> mPair = toMajoranaPair(dEnc.first[1] => dEnc.second[1]);

julia> mPair == (PauliSum(Int, [pauli"X"]) => PauliSum(Int, [pauli"Y"]))
true

Paulimorphic.toString — Method
toString(pStr::PauliStr; denseString::Bool=false, omitPlusSign::Bool=denseString) -> 
String

Return a String representation of pStr::PauliStr. The returned String is prefixed by the marker of pStr.phase, represented by "+", "+i", "-", or "-i". When omitPlusSign=true, the character '+' is omitted.

When denseString=false (the default sparse representation), identity sites are omitted and each non-identity Pauli character carries its (1-based) site index as a subscript (e.g., "+X₁X₂X₄"). The body (excluding the phase prefix) also collapses to "I" whenever every site carries the identity (including the zero-site case).

When denseString=true (the dense representation), every site in 1:pStr.n emits one character ('I', 'X', 'Y', or 'Z'). In this format, the returned value can be accepted by @pauli_str as a string literal.

Info

When pStr is a zero-site string, the body of the returned string (after the phase prefix) is "I", so parsing it back with @pauli_str yields a single-site identity rather than a zero-site string:

julia> countSites(@pauli_str toString(pauli"-", denseString=true)) == 1
true

Examples

julia> toString(pauli"XXIX")
"+X₁X₂X₄"

julia> toString(pauli"XXIX", denseString=true)
"XXIX"

julia> toString(pauli"-iXXIX", denseString=true)
"-iXXIX"

julia> let s = pauli"-XXIX"; (@pauli_str toString(s, denseString=true)) == s end
true

Base.isless — Method
Base.isless(a::PauliStr, b::PauliStr) -> Bool

Compare two PauliStr under a deterministic total order consistent with ==, and return whether a orders strictly before b. Four attributes are compared in the following order based on their priorities (with the first mismatched attribute deciding the result):

  1. Explicit site count: evaluated via countSites, in ascending order.
  2. Pauli weight: evaluated via countWeight, in ascending order.
  3. Operator content: comparison of the highest-indexed site where a and b carry different single-site operators, which follows the value order of PauliSym: symI, symZ, symX, symY.
  4. Phase: comparison of the Z₄ exponent of .phase::PhaseFactor such that all possible phase values follow the order: +1, +im, -1, -im.

Every attribute is defined purely in terms of the operator content of each compared string regardless of the underlying storage buffers' word size (8*sizeof(UInt)). This order underlies the canonical term order of PauliSum.

Examples

julia> pauli"II" < pauli"ZI" < pauli"XI" < pauli"IZ" < pauli"IX" < pauli"XX"
true

julia> pauli"X" < PhaseFactor(1) * pauli"X" < PhaseFactor(2) * pauli"X"
true
